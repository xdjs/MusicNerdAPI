# Conversation-driven canvas preview

Branch-only extension to the existing artist chat route. Optional canvas.v1 requests use the existing MODEL_CHAT, instructions and stored-source search/read tools, adding a typed composeCanvas tool. Ordinary chat requests retain existing behavior. LATASHA and Dutchyyy staging IDs are allowlisted. No arbitrary generated code or model-owned source URLs.

The complete next spec is validated against server-owned evidence and pinned blocks. A successful turn emits data-canvas after the stream finishes. Failed or aborted turns cannot commit a candidate. Clients verify session, turn and revision before committing.

### Focused retrieval (preview extension)

The existing `searchSources` searches eligible stored public Lore, own posts, published interview answers and Latest provider originals. It is not restricted to the curated seed. Canvas `readSource` additionally accepts optional `focus` (1–300 characters): the model receives a bounded relevant window and the card receives an exact, at-most-25-word excerpt. Its evidence ID includes a server-derived character offset (`sourceId::excerpt:offset`), allowing a later request to reconstruct the same passage from loaded public originals. A new focus creates a separate evidence reference instead of rewriting an existing pinned passage. Unknown or other-artist IDs remain unavailable. Provider activity dates retain release/activity meaning.

### Public PDF page retrieval

The general public research loader excludes all `file_path` rows. Inspection found a distinction: the upload completion handler publishes authorized files to the public vault-files bucket, saves approved sources, and the anonymous claimed profile exposes download links; temporary uploads are kept in a separate staging bucket. The general loader remains unchanged.

The preview adds only two exact Dutchyyy PDF URLs already verified as public profile download links. Every request rechecks actual href links in the anonymous public profile before fetching either file. No private database rows, storage credentials, staging objects or arbitrary model-supplied URLs are read. Redirects reject; profile bytes cap at1MB; each PDF at2MB,20pages and120k characters, with timeouts. The existing pdf-parse dependency extracts physical pages into memory, with no database writes or persisted full text. Current files yield19+13pages. Page-specific server-owned originals join the existing searchSources/readSource pipeline. IDs contain a document revision hash and physical page; citations use #page=. Missing publication links or failed extraction produce coverage limitations, not invented text.

Page metadata preserves document versus artist statements, the Dutchyyy preface versus Sound of Fractures foreword, and recording/release/upload distinctions. Never treat AI dialogue or editorial narration as an artist quote. The original16-page Gemini dialogue and the separate41-page archive are not part of this bounded retrieval set. This is not whole-archive ingestion.
