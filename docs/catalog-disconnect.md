# Catalog disconnect and explicit replacement (#1580)

Status: local design/implementation; requires a reviewed Web-owned migration and separately authorized live schema/privilege application before release. No historical artist sweep or exclusion is included.

An authenticated claimant/admin may clear the Spotify or Deezer account they are viewing through `POST /api/directEditLink`, with `action: "clear"`, `siteName`, and `expectedValue` (the displayed account ID; explicit null means already disconnected). `removeArtistData` retains its contributor/admin authorization but also requires the displayed catalog ID and captures the approved-claim generation. Other platforms retain existing behavior. A changed identity or claim is a conflict/refusal. Definite SQL failures roll back the whole transaction; a transport failure during COMMIT can be uncertain, so generic errors require refresh before retry. The normal explicit set path continues to enforce other-artist/direct/mapping collisions.

The Web follow-up moves only these two endpoint clients to the existing Privy bearer/API URL mechanism, then removes their Web routes. This is the bounded #1595 row H integration, not the remaining row's migration. No live staging submission is used as verification.

## Private function contract

`musicnerd_private.disconnect_catalog_link(artist_id uuid, platform text, expected_value text, expected_mapping jsonb, actor_user_id uuid, expected_claim_id uuid, authorization text) RETURNS text`.

- Only `spotify`/`deezer`; authorization is `owner` or `contributor`. The authenticated backend derives the actor, not a request body. This is a trusted backend contract, not independent Supabase JWT/auth.uid verification.
- The caller takes the existing artist/platform advisory lock and captures the complete mapping row with `to_jsonb`. The function independently takes that same slot lock, the expected provider-ID lock, then the artist row lock. It rereads the current approved claim without taking a claim row lock (revocation takes claim before artist), verifies its exact expected generation, and rereads current actor role/ownership. Owner requires claimant/admin; contributor requires whitelisted/admin. No missing actor/context fallback.
- Under the locks, the exact direct value must equal `expected_value`, and the current full mapping snapshot must equal `expected_mapping`. Any mapping must belong to this artist/platform and equal the direct old ID. A divergent mapping or an already-null field with a retained mapping is a 409 requiring explicit review; it is not silently removed. Null field plus no mapping retains explicit pending identity-job cancellation but creates no archive event. A stale repeat has no new archive entry.
- Insert a private immutable disconnect event from DB-derived values: independent event ID, artist/platform, direct old value, complete original mapping JSON (all 11 fields including original attribution), actor/user, authorization, approved claim ID, timestamp. Snapshot identifiers have no cascading or restrictive foreign keys to artist/user/claim/mapping rows.
- Remove only that exact active mapping ID/artist/platform (assert one row), clear only the observed direct column, cancel only pending/running spotify_match jobs for this artist. Archive failure, stale CAS, authorization failure or any later failure rolls back every mutation.
- No exclusion, Latest snapshot, bio, unrelated platform, other artist, source or prior audit is changed. Existing Latest reads omit snapshots when the corresponding account is disconnected. A future explicit valid replacement passes normal collision guards; ordinary disconnect does not prohibit future independently corroborated rediscovery.

The migration creates a new dedicated private schema, failing if it already exists rather than changing unrelated grants; its entire DDL/privilege change runs in an explicit transaction. The private schema/table has no browser/PUBLIC access and no mnweb table read/write privilege. The SECURITY DEFINER function is owned by the trusted DDL role, has fixed `pg_catalog, pg_temp` search_path and fully qualified relations, and grants only schema USAGE/function EXECUTE to backend mnweb. No general mapping DELETE privilege is added. This is new security authority and must not be applied live without explicit action-time approval.

## Other callers

Catalog MCP deletion has API-key authority but no authenticated user/claim proof; it must fail closed with an actionable instruction to use the authenticated disconnect endpoint. Noncatalog MCP deletion stays unchanged. This is an explicit compatibility change, not an implicit capability expansion. Legacy onboarding removals carry only names, so Spotify/Deezer removal is rejected before applying any decisions. Both confirm and find-more turns return an actionable profile-editor error without confirming, advancing, or starting discovery. Additions and noncatalog removals keep their existing contract. Research/build reset preserves both catalog identities and mappings; it does not substitute for disconnect. No automatic discovery/removal receives owner authority.

## Recovery and verification

The archive is reversible evidence, not an automatic undo API. Any targeted restoration is separately authorized and first checks no newer direct value/mapping and no other-artist owner; never overwrite a collision or restart canceled jobs blindly. Local tests use an isolated database and actual migration/function under mnweb, covering clear→valid replacement, wrong/stale mapping and UI values, caller/claim changes, collisions, archive failure rollback, preserved other data and excluded old Latest snapshots. Live schema/grants, authenticated UI/provider identity acceptance and owner sign-off are separate gates.
