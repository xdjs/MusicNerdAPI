# Bounded saved-source discovery and reads

Artist chat retains its existing six tools, streaming loop, low effort, source eligibility and request quota. Relevance discovery ranks distinct eligible originals before its existing eight-source cap. A navigation excerpt preserves contiguous context inside the winning passage, up to 800 UTF-16 characters, and reports truncation/context limits. Discovery is not citation evidence.

An optional source/revision-bound locator from discovery can be copied to `readSource` to obtain the matched context within the unchanged 12,000-character read bound. Invalid, foreign or stale locators fail without prefix fallback. A source-ID-only read retains the existing prefix response. Coordinates refer to the turn's loaded original snapshot; the composed handler separately revalidates its current publication and revision during exposure and before subsequent model steps. It does not refetch the external article.

PDF discovery ranks filename and stored extracted-text topic matches, including Unicode terms. The original PDF must still be read for claims and physical-page citations. The extraction digest detects changes since discovery, not agreement with PDF bytes. Approved-source, public storage URL/path, size and artist constraints remain.

This retrieval overlay requires #1655's compatible schema and API/Web readers. Approved `public` Lore is readable without a claim; `inherit` retains #1655's approved-claim or submission-time trusted-contribution-event gate. Private, pending and rejected vault records remain excluded. The protected public-text reader and safe uploaded-text citation URL path are preserved. It does not infer trust from a contributor's current role or invent historical attribution. Publication decisions remain a separate audited writer concern. Search metadata, reads and evidence reused at subsequent model steps revalidate publication/revision; linked private research copies remain excluded. Old readers must not be restored after private decisions exist. A public storage URL is not cryptographically revoked by this reader policy. This overlay does not replace #1655's coordinated migration, restricted-role and derived-content release gates.

Retained unlinked research copies also use the existing persistence URL canonicalizer for private exclusions. Its host/trailing-slash/tracking aliases cannot bypass that check; edition parameters and path case remain distinct in the tested controls. Identity retains the canonicalizer's existing rules, including removal of `s` and `t`, so it does not preserve every potentially meaningful query parameter. The private URL-key query is artist-scoped and bounded, and adds metadata work when public discovery originals are loaded or service evidence is reopened; parallel checks can multiply this work. Existing pre-load corpus limits remain conservative before this alias filter; an oversized raw candidate set can fail closed rather than be loaded for filtering.

This changes evidence availability, not semantic answer guarantees. Source conflicts, full requested-set coverage, native-PDF perception and browser/follow-up answer quality require separate acceptance. The routed first/earliest and alias-inventory candidate adds original-bound physical-page text extraction, revision/hash-bound continuation and literal attributed output. It does not add a verifier or extra model stage, enable an execution manifest, or change the target model effort. Literal selections can still be incomplete or unhelpful; valid provenance and completed transport are not semantic acceptance. About/Lore generation, trusted-submission writes and claim/onboarding preservation remain coordinated under #1655 rather than duplicated here.

Verified PDF text is available per physical page. Empty or whitespace-only extraction retains its original page number, exact extraction hash and a `no-extracted-text` status, but has no selectable passage IDs. Other verified pages remain selectable. This status does not establish that the rendered page is blank or contains no relevant information. Mixed inventories remain partial in the UI and incomplete/unscored for automatic evidence grading; native original bytes and current-source checks are unchanged.

Model metadata carries document identity once at the PDF root. Page records keep every literal character, physical page/hash, offsets and selectable block IDs/qualification flags. Repeated identity and block previews are omitted only because they can be reconstructed exactly from that root and full page text; full server evidence remains unchanged. The existing parser bounds/deadline, passage output bounds, evaluator input/capture ceilings and model/tool/read limits still apply. This compaction is not fact selection, a completeness guarantee, or authorization to raise evaluation limits.
