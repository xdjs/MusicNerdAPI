# About and trusted Lore integration (local candidate)

Issue: MusicNerdWeb #1655. This integration is local, unreleased and not live-verified.

About preparation and Lore summaries consume only approved evidence eligible under the existing source-publication policy. Explicit private, pending and rejected sources are excluded. Inherited sources require an approved claim or an exact immutable trusted-submission event; a contributor's later role loss does not remove submission-time trust. This does not grant contributors regeneration or profile-edit authority.

Lore revisions bind source identity, provenance, publication and evidence content. Under the artist lock, About and Lore publication compare the current eligible source set with the generated manifest. Onboarding document publication receives the same check. Administrator authority is held through the short write transaction. Model work never holds those locks.

Directory preparation has its own assessed-source provenance. Its public projection and claimant draft reuse preserve that contract while rejecting private or unknown publication states. Reused claimant drafts carry current revision-bearing evidence, and publication revalidates it. Claiming must not erase trusted contributions.

Public Web llms.txt requires a current claim and valid current vault revisions; it hides the whole document when recorded evidence is private, rejected, removed, revised or legacy/unversioned. Owner/admin private reads are unchanged.

Remaining boundaries: claimed About text has no durable bio-to-evidence association. Independently refreshed artist_docs cannot prove the provenance of artists.bio or pinned history. That pre-existing display gap needs explicit provenance across generated/current/history writers before this combined candidate is release-ready. This integration does not invent legacy provenance or silently hide manually authored bios. Upload/storage deadline and physical object cleanup work remains separate. Provider-free PGlite checks do not establish multi-connection production PostgreSQL concurrency or live provider behavior.
