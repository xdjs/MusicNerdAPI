# Ordinary chat offline trace contract

The test-only adapter in `lib/chat/__tests__/ordinaryChatTrace.test.ts` exercises the ordinary `postArtistChatHandler`, installed AI SDK tool loop and UI-message decoder. It does not introduce a request flag, endpoint, production observer or provider configuration. Source loading, identity, quota and providers are substituted; this is implementation evidence, not real authorization or autonomous answer acceptance.

Each run records its request, supplied corpus revisions and metadata, actual scripted query/tool events, ordered returned candidates, exact SDK model inputs, raw SSE, citation events, client-decoded messages and observed transport termination. Read offsets are verified against the exact original slice and, for contextual reads, the returned source revision. Legacy reads without offsets are checked against the source prefix. Scores/quality fields absent from the runtime are not invented. The six-step ordinary limit and eight-source discovery cap remain unchanged. Missing `finish`, errors and aborts are recorded, not converted into success. Source truth, claim support and completeness require separate evaluation.

The adapter requires a mock model, blocks fetch and Node network entry points, and substitutes external web/PDF/database dependencies. It imposes zero SDK retries and a 2,048-output-token request setting for offline tests only. Its recorder admits one request, at most six model steps, 128,000 serialized input bytes per step, 8,192 output characters and a 1,000,000-byte serialized event-ledger limit. That counter bounds only `recorder.events`; it does not bound the total returned artifact or process memory. Raw stream strings, client snapshots, model calls and provenance are retained separately, and provenance can duplicate full source text. Limit failures do not truncate evidence, retry or resume. These are test resource bounds, not production spending controls, tokenizer guarantees or permission for live execution.

The final returned `terminal` together with `trace.failure` is authoritative for capture validity. An event-ledger `transport-end` entry can record `completed_transport` before provenance finalization exceeds the ledger limit; that earlier entry alone must not be interpreted as a complete successful capture. In that case the returned terminal reports `capture_incomplete` and `trace.failure` reports the limit failure while already collected results remain inspectable.

Relevance discovery now returns a bounded snippet from the winning ranked window plus an optional absolute UTF-16 locator (`sourceId`, `revision`, `start`, `end`). Passing that locator unchanged to `readSource` opens up to 12,000 characters around the window with at most 800 preceding characters. Invalid, mismatched or stale locators return an error without citation or prefix fallback. Source-only reads retain their prefix behavior; latest/platform discovery keeps its existing chronological path. No extra provider call, mutable search cache or streaming change is introduced. The locator identifies context within the request-authorized source snapshot, not proof of claim support or current database authorization beyond existing loader behavior.

Retained negative regressions expose current limitations: source-only readSource omits text after 12,000 characters; a valid citation can accompany unsupported prose; a tool-only exhausted trajectory is not a useful answer. Scripted queries are explicitly not evidence that the model would choose those queries. The separate private paired-client check uses current Web display helpers; it does not substitute for React/browser acceptance.
