## Local #1424 discovered-web reader candidate

The local candidate preserves ordinary incremental streaming and low effort. It does not add answer buffering, a verifier or automatic regeneration. It adds `readWebSource` for opaque source IDs registered by the current turn's web search; arbitrary URLs and old-turn IDs are not accepted. At most two reads are attempted, failures count, and concurrent duplicate reads share one request. Public DNS pinning, redirect validation, HTML/byte limits and a five-second network cancellation budget reuse the existing source reader. Request cancellation propagates to the fetch. Synchronous parsing cannot be preempted, but results past the deadline are withheld after metadata parsing. These are resource controls, not a hard CPU execution limit.

A successful read returns the exact bounded original excerpt, final citation URL, requested URL, source ID, publication/retrieval dates and truncation. `readChatEvidence` and the normal streaming eval retain these fields and the passage hash. Failed reads are not evidence. Search snippets and read excerpts remain distinct observations. Neither a search ranking nor a successful read establishes primary authority or semantic correctness.

The earlier date metadata correction remains: publication, activity and retrieval dates seen by the answer model must not be omitted from evaluation. Stored-source read coverage is explicitly reported, without claiming stored text is the complete original document.

New primary-source gold is versioned separately from the historical Q2 fixture. The old unsupported billing citations remain failures. The new evidence distinguishes earlier participation from a full album collaboration, without asserting unverified guest or co-lead roles. Do not retrospectively use newly found text to grade an answer that never received it.

Offline tests establish tool/citation/capture behavior and early text streaming, not correct model source selection, injection resistance or live answer quality. Before publication, review the API/Docs contract and verify the exact preview UI path with a separately approved bounded test. Inspect each claim against the source it cites; successful HTTP or markers alone are not acceptance.
