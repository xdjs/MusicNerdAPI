A safe unnecessary refusal fails an answerable case. An insufficient-evidence answer must not claim a corpus-wide absence from a small retrieved subset. Model scores assist review; they do not certify correctness.

Local integration candidate: `showSourceDifferences` is a terminal tool for two saved text sources successfully read in the current turn. A unique literal anchor selects a complete paragraph with nearby preceding context and a following paragraph; short preceding headings/date blocks are retained. Ambiguous, unread, oversized or terminally truncated selections fail without emitting an answer. The server renders fixed attribution and contextual excerpts, never a model-written reconciliation, then stops the SDK loop without a further model call. Literal source brackets use full-width glyphs so the existing Web citation parser cannot turn them into new citation markers. This does not reconstruct missing stored text or establish that the sources genuinely conflict. Model selection and relevance still require live acceptance. Web snippets and PDF-only questions retain their existing tools.

Streaming tradeoff: tool events still stream, but answer text is held until its model step completes. Text from tool-bearing intermediate steps is discarded; a selected fallback replaces same-step model prose. Error/abort closes discard buffered text. Ordinary terminal answer content remains unchanged, including the PDF path, but first-useful-text timing can increase because its text no longer appears token by token. This requires performance/UX acceptance before publication. Offline handler/SDK-loop tests prove rendering and stop behavior, not model choice or end-to-end speed.
