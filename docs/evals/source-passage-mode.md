# Source-passage response mode — local candidate

Existing POST /api/artist/{id}/chat accepts optional `responseMode: "source_passages"`. Omission keeps the current streaming/PDF route unchanged. This explicit mode is for attributed excerpts from the artist's currently authorized, approved saved text sources only; no PDF, creative generation or live search is provided by this mode. Client adoption/default routing is a separate product integration decision, not a model-selected fallback.

The model can search saved sources, request complete context around a source anchor, then select one returned opaque passage ID at a time. It cannot supply displayed prose, citations, URLs or arbitrary character spans. The server revalidates the selected source against a fresh authorized artist snapshot before emitting its exact context with fixed attribution. Plain model text and model tool payloads never merge into the client stream. `data-evidence-mode` version 1 declares the mode; each `data-evidence-passage` carries literal text, separate citation metadata and source dates. `data-evidence-status` carries a fixed failure code. The client renders source words as plain React text, without Markdown or citation cleanup. Each complete validated selection streams immediately; there is no whole-answer buffer or second verifier.

At most two selections, six model steps, 1,024 output tokens per step, zero SDK retries. Passage context is at most 6,000 characters; registry at most four passages/24,000 characters. Source reads examine at most 12,000 stored characters. Existing complete-context selection preserves adjacent blocks/headings and refuses ambiguous anchors, oversized context and a known truncated terminal block. Historical missing context cannot be recovered automatically.

Unknown, duplicate, invalid, changed or revoked selections stop further selection output and produce a fixed validation-status message. Missing selection yields a fixed inability-to-validate status, never an assertion that evidence does not exist. Cancellation stops emission. A source revoked after an already-emitted excerpt cannot retract prior streamed text. Validity is checked immediately before emission; no durable grant or source write exists.

This boundary guarantees displayed excerpt bytes/citation provenance come from validated server-held context, not generated bridge claims. It does not guarantee the model chooses relevant excerpts, sources are true, context is exhaustive or the user's question is fully answered. Injection-like instructions inside a source remain literal attributed quotations, never actions. Up to two previous passage texts (6000 characters each) are retained as explicitly untrusted conversation hints for follow-ups; their IDs, citations and authorization are not reused. Current source authorization is always checked again before any new display. Actual live model selection, real Web rendering and latency remain untested.

# Preview experiment spending policy

Only when `VERCEL_ENV` is `preview`, this experimental mode reserves an estimated maximum of $0.15 per request before each provider call. Ordinary chat and production do not use this policy. It preserves the existing six-step, 1,024-output-token limits and zero SDK retries; provider routing is limited to Anthropic for this test. The guard does not truncate messages or evidence to fit.

Reservation counts the complete SDK-prepared parameters (system, messages, tool schemas and options) as UTF-8 bytes plus 2,048 estimated framing tokens, at $4.40/M input and $11/M output with the full output allowance. The input rate includes a two-times regional-input cache-write allowance. This deliberately conservative heuristic is **not** a provider tokenizer or guaranteed invoice ceiling. SDK/Gateway serialization and provider internal attempts remain outside that guarantee. Three distinct admitted requests reserve at most $0.45 under these assumptions.

Reservations are never refunded. Missing/invalid usage, underestimated usage, abnormal termination, incomplete streams or receipt-write failure stop further generation. Previously displayed validated passages may remain, followed by the existing failure status; such a result is partial, not a passing acceptance test.

Transient `data-preview-budget` SSE records include a request-local ID, `reserved`, `reconciled`, `complete` or `stopped` phase, step/counts, cumulative reserved and observed upper-estimate USD, actual input/output totals and a Gateway generation ID when supplied. They contain no source text, credentials or personal identifiers. These events are capture-only, not answer content. The tester must retain request-bound SSE and inspect receipts between questions; absent/incomplete captures mean no next submission or retry. Observed upper estimates are calculated from usage, not invoices.
