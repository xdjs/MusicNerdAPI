# Single-case staging runtime

The manual Evals job already has the required staging database, Gateway, Tavily, allowance and private Braintrust secret bindings. Their values are not copied into local files or shared environment settings. The job derives a public Supabase origin only from a recognized direct/pooler Postgres endpoint, then the runner validates that origin against the manifest hash.

The explicit `chat-single` selector has two phases. `preflight_only` defaults to true. Its standalone bundled entrypoint imports no Braintrust Eval, performs ordinary artist/source/PDF/visitor reads, verifies every pinned original locally, and returns before constructing a model, creating a claim or trace, or reserving quota. Its safe summary reports counts and a complete normalized-corpus fingerprint. A disabled manifest may be used for this phase. Missing or changed corpus pins prevent execution. The pinned Braintrust CLI's bundler is reused; no new dependency is installed.

The execute phase requires a separately reviewed enabled version-2 manifest, exact commit/manifest/code/date/request/schema/source pins and run_attempt=1. Its model is the unchanged MODEL_CHAT, never a manifest-selected replacement. The manifest explicitly pins either Anthropic or Vertex as the serving provider of that same Sonnet model; there is no model fallback. Provider choice affects recipients, terms and possible behavior and must be approved. A different evaluator model is not production-model proof.

The existing chatStreamTurn invokes the ordinary handler, full six-tool catalog, automatic choice and bounded loop. The current Web's 12,000-character capability is explicit. Actual handler-loaded originals are fingerprinted only through the trusted in-process observer; this event never enters the HTTP stream. The guard refuses to forward without that matching observation. Full eligible PDF catalog checks run after discovery and before forwarding; actual selected originals retain their own revision/hash/read revalidation. These checks do not filter or substitute data and do not make source snapshots atomic.

PDF input/capture limits are the reviewed V6 values. One synchronous private JSONL sink accounts for guard and outer tool/UI/terminal events and shares its abort signal. Corrupt/partial JSONL remains preserved and yields an explicit failed receipt instead of a repaired success. Failed or empty literal/prose transport flushes a safe private failure before the Eval fails. No judge or replacement is run. Ordinary suite code remains unchanged in its else branch.

The custom ledger bound is not a memory, raw-stderr or total Braintrust-upload bound. Braintrust receives the structured turn and ledger, including additional assembled evidence copies. Installed automatic AI SDK/Vercel instrumentation is disabled. Native bytes/base64 are excluded from the custom ledger, but provider errors can still place request data in the private ephemeral console file. Neither console nor raw evidence is uploaded as a public artifact. Retention and upstream billing attempts remain separate approval facts.

Claims and DISPATCHED markers prevent repetition inside one run; they are not a cross-workflow global ledger. The named execution owner must inspect prior run/claim state before one dispatch. No unknown-outcome request may be replaced. The 20-second normal handler goal is unchanged; preflight time is separately reported, not hidden in a latency pass. A 150-second abort timeout is a safety deadline, not the goal.

Publication of the exact compatible API/Web candidate, normal CI/preview, a read-only preflight dispatch and any later enabled-manifest publication/provider dispatch require their applicable approvals. No new credential, role grant, claim fixture, source edit, production release or retry of a denied role is part of this path.
