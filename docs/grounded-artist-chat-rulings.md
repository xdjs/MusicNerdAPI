# Grounded artist chat: rulings made during execution of part 1

Recorded 2026-11-13. Part 1 was executed task by task by subagents, each task reviewed before the next, each branch reviewed as a whole afterwards. Wherever the plan was silent, a reviewer and the plan disagreed, or a finding needed a call, Claude (as controller) ruled so the work did not stall. Every ruling is listed here in the order it was made, with what it costs if it is wrong, so Pete can overrule any of them. The approved design (`grounded-artist-chat-design.md`) stayed the authority throughout.

- **R1.** Task 14 spend guard fails closed only for gateway paths ending in `-model` (language-model, embedding-model, image-model); other gateway paths pass through unpriced as today — a non-model metadata call must not break every suite — cost if wrong: an unpriced model path slips through until the first hosted run shows it.
- **R2.** `ingestSource` gains `pdfTimeoutMs?: number` (default `PDF_PARSE_TIMEOUT_MS`, 10 s); `runUnitSync` passes 45 s — the backfill must read long documents while uploads stay bounded — cost if wrong: a slow document stalls one slice.
- **R3.** Task 13 extracts the evidence eligibility predicate into `lib/sourcePublication/publicEvidenceSql.ts` and uses it in both `eligibleUnitsSql` and `loadPublicResearchOriginals` (its integration tests cover the refactor) — DRY per spec principle "one ingestion path" — cost if wrong: a behaviour change in the legacy loader, caught by its tests.
- **R4.** Task 1 branches from Web `origin/main` (b3bf4076, migrations through 0065); the migration is 0066 — the local `main` clone is stale — cost if wrong: renumbering.
- **R5.** A1 branches from API main after #117 (7a171a6); #120 (re-landed #118) is merged before Task 17 (it needs `keepCurrentPdfTurns`/`validateArtistChatBody` from #118) — cost if wrong: a rebase of A1.
- **R6 (security review on 0066).** add `AFTER DELETE` triggers on `artist_vault_sources`, `artist_social_posts` and `artist_research_evidence` that delete the matching `source_units` rows (functions `SECURITY INVOKER SET search_path = ''`, EXECUTE granted to mnweb, pattern of 0039) — eligibility is already joined at query time (Task 13), but deleted-source text must not linger in the table until `unit_sync` prunes it — cost if wrong: one more trigger to maintain; no behaviour change for readers.
- **R7 (security review, update-visibility gap on 0066).** no update trigger; Task 13 `eligibleUnitsSql` joins every unit to its live source row with the publication filter and `source_revision` equality, so a status/publication/text change hides units at the next query — the finding lists this join as the alternative — cost if wrong: none for readers; stale rows linger until `unit_sync` replaces them.
- **R8 (security review, insert-after-delete race).** Task 8 `writeSourceUnits` runs in one transaction that first locks the source row (`select 1 from <kind table> where id = $sourceId for key share`) and writes nothing when the row is gone (returns 0); the AFTER DELETE triggers then cannot be bypassed by a concurrent ingest — cost if wrong: one extra statement per ingest.
- **R9.** Task 1 brief said "widen nothing else" in schema.ts, but the global constraint says both schema files are updated; the mirror of `artist_research_jobs_kind_check` gains `'unit_sync'` and the snapshot is regenerated, else the next `drizzle-kit generate` would drop the kind — cost if wrong: none; it matches the database.
- **R10.** the shared pdf-parse page renderer lives in `lib/units/renderPdfPageText.ts` (one function per file), imported by both `extractPdfPages` and `readPdfChatEvidence` — cost if wrong: one extra small module.
- **R11 (security review on buildSourceUnits, cost amplification).** add `MAX_OCR_PAGES = 60` to `lib/units/types.ts`; once a document has sent 60 pages to the vision model, further broken pages are skipped and `failed: "vision"` is set; the loop checks `deps.signal?.aborted` each iteration and stops (also `failed: "vision"`) instead of trying every remaining page — bounds the paid calls per upload to about six cents on Flash — cost if wrong: a scanned document over 60 pages loses its later pages until the cap is raised. Reusing one pdf-lib document across slices is deferred as a minor.
- **R12.** the one-time OCR fill of a null `extracted_text` happens only when the read is complete (`failed` unset), and it runs before the units are stamped, using the post-update revision — a partial read must not become a permanent blob, and units must carry the revision readers will see — cost if wrong: a scanned document with one failed page keeps a null blob until a later complete read.
- **R13 (Task 11 review).** inline ingest at upload never runs the vision pass and is bounded. `ingestSource` gains `ocr?: boolean` (default true) carried to `buildSourceUnits` deps; with `ocr: false` a broken page is not sent to the model and the build reports `needsOcr: true`; `ingestSource` then writes nothing and returns `skipped: "needs-ocr"` (new union member). `ingestUploadInline` calls ingest with `ocr: false`, `AbortSignal.timeout(20_000)` and a 5 s inspect signal, and queues `unit_sync` whenever the outcome is `needs-ocr`, carries `failed`, or the call threw or aborted. Handlers call it after `refreshAfterUpload`/cleanup, last before the response. Matches the design ("OCR … go to the research-jobs queue") and keeps the upload under the 60 s route limit — cost if wrong: scanned uploads become searchable a minute later (next cron tick) instead of at once.
- **R16.** staging has no API worker to drain `unit_sync` jobs, so the retrieval eval gets a hosted `units-backfill` suite that ingests every source of the three eval artists in-process through `ingestSource` (bounded, OCR on, embeddings on) and scores `units > 0`; it runs once after Pete applies 0066 to staging and before the retrieval eval — cost if wrong: a few cents of embeddings on staging and one more suite to maintain.
- **R17.** one extra small fix round for that residual instead of parking it — a known lost-wakeup bug must not ship on a branch that auto-publishes; the fix is one destructure plus a test — cost if wrong: one more short review.
- **R18.** `createChatCitations(writer, seed)` seeds carried numbers (url → n, part written at once, next number after the highest seed, gaps preserved) and `createChatDocuments` throws if a prior registration returns a different number — a follow-up must keep earlier numbers even with holes — cost if wrong: Task 18 must seed the cite from prior; a mismatch is loud, not silent.
- **R19.** `readUnits` tool `locators` is optional (0 to 6); omitted or empty means every unit of the document in order, bounded by the token budget — otherwise "every item" questions cannot read a document whose locators are sections the model has not seen — cost if wrong: a bigger read per call, still capped by READ_UNITS_TOKEN_BUDGET.
- **R20 amended.** the running union covers every earlier assistant answer, kept or not (the implementer showed "kept only" fails scenario 1) — a withdrawal or an edit of a document drops every later answer in that conversation — cost if wrong: follow-ups lose more history than strictly necessary after a document changes.
- **R21 (I4 reading).** in `units-backfill`, a source the run found to have no text (ingest outcome `skipped: "no-text"` or `not-found`) is left out of the stale count, so `indexed` can reach 1 — otherwise a text-less source scores 0 forever — cost if wrong: a source that should have text but extracted none is not flagged by this suite (the ingest outcome counts still show it).
- **R22 (Task 11b).** the Web hook also fires when a vault source is created already approved (source-backed UGC approval; trusted `insertVaultSource`), not only on status/publication changes — the purpose is that any newly eligible source gets indexed — cost if wrong: an extra idempotent upsert per approved insert.
- **R23.** one small residual round for those three (same reasoning as R17: a known replay bug must not ship) — cost if wrong: one more short review.

## Calls worth Pete's attention first

- R13: inline indexing at upload is text-layer only; scanned pages wait for the queue (about a minute).
- R11 and R14: at most 60 pages of one document go to the vision model; a read cut short is retried once, then stamped partial.
- R20: after any document an answer relied on is withdrawn or edited, that answer and every later answer in the conversation are dropped from the history the model sees.
- R15 and R22: the index catches up after uploads, after text-producing research jobs, and after Web approvals or approved inserts.
- R16: staging is indexed by a hosted eval suite, because staging has no API worker.
- Published interview answers stay on the existing "latest" path in this version (design correction of 2026-11-13).
